   - **PreToolUse 인라인 가드레일**: 코딩 에이전트가 고정 평가 데이터셋(Golden Dataset)을 변조하거나 서버 프로세스를 임의 조작하는 비인가 시스템 명령을 실행 직전 인터셉트하여 원천 차단했습니다.
   - **Commit-lint 프리커밋 게이트**: AST 파싱 검사를 결합하여 기존 테이블이나 컬럼의 DROP/ALTER를 유발하는 파괴적 마이그레이션 커밋을 물리적으로 거부했습니다.
4. **사용자 경험(UX) 및 작업 연속성 개선**:

### [프로젝트 2] Helpnow Foundry Q&A 게시판 Full-stack 구축

- **기간 / 역할**: 2026.08 (약 2주) / 정책 협의부터 화면·API·DB 단독 설계 및 풀스택 구현 (기여도 100%)
- **핵심 기술**: Next.js, FastAPI, PostgreSQL, MinIO, Keycloak IAM, 클라우드(AWS) 환경 배포, 보상 삭제 로직, DB 고유 제약 조건, Claude Code CLI, Orca ADE, Playwright MCP

#### 배경 및 문제 정의

- **고객 문의 창구 분산에 따른 리소스 낭비**: 엔터프라이즈 고객의 기술 문의가 Google Chat과 임시 버그 창구로 분산되어, 동일한 기술 질의에 대해 담당 엔지니어들이 중복 대응해야 하는 생산성 저하가 발생했습니다.
- **파일 누수 및 동시성 문제 해결 필요**: 사내 클라우드(AWS) 환경 기반의 Helpnow Foundry 플랫폼 내에서 Keycloak 로그인 및 표준 UI와 통합되는 1:1 Q&A 게시판을 단독 개발하는 과정에서, 다중 첨부파일 업로드 도중 에러가 발생했을 때 파일 저장소(MinIO)에 쓰레기 파일이 남아 용량이 낭비되는 문제, 관리자 답변이 동시에 등록되어 문의 1개에 답변이 중복으로 달리는 동시성 문제, 그리고 개발자 에러 로그(`<TypeError>`) 노출 시 발생할 수 있는 보안 취약점(XSS)을 해결해야 했습니다.

#### 핵심 공학 구현 및 시스템 가드레일

1. **첨부파일 저장소 누수 방지 및 실패 시 즉시 보상 삭제 구현**:
   - 여러 파일을 올리던 중 5MB 용량 초과 등으로 DB 저장이 실패했을 때, DB는 롤백되지만 MinIO 저장소에는 앞서 올라간 정상 파일이 삭제되지 않고 남아 용량을 낭비하는 고아 파일 누수 문제를 확인했습니다.
   - 이를 막기 위해 파일 크기와 형식을 서버 수신 즉시 먼저 검사(선검증)하여 잘못된 파일은 업로드 자체를 사전에 차단했습니다.
   - 업로드 도중 네트워크 에러나 DB 저장 실패가 발생하면, 해당 요청으로 방금 저장소에 생성된 파일들을 즉시 역추적해 강제로 삭제(보상 삭제)하도록 구현했습니다. 네트워크 장애 등으로 삭제에 실패한 파일은 예외 로그에 기록한 뒤, 30일이 지난 미참조 파일을 자동 정리하는 배치 규칙을 적용해 저장소 누수를 0개로 통제했습니다.
2. **DB 고유 제약 조건을 활용한 답변 중복 등록 차단 및 안전한 원문 표시**:
   - 여러 관리자가 동시에 답변을 달거나 중복 클릭할 때 답변이 여러 개 등록되는 경쟁 상태를 막기 위해, 단순 코드 검사가 아니라 DB 테이블 자체에 '문의당 유효 답변은 1개만 가능'하도록 고유(UNIQUE) 제약 조건을 적용해 동시 요청에도 데이터 정합성을 유지했습니다.
   - 개발 고객 문의 특성상 본문에 `<TypeError>` 같은 시스템 태그가 자주 들어가는데, 단순 태그 제거 방식을 쓰면 원문이 훼손되므로 원본 글자는 그대로 보존하되 React의 텍스트 출력 방식을 통해 브라우저가 이를 스크립트가 아닌 순수 글자로만 표시하게 만들어 XSS 공격을 안전하게 차단했습니다.
3. **AI 개발 하네스 실무 도입을 통한 단독 3일 배포 완수**:
   - Claude Code CLI의 컨텍스트 망각을 제어하기 위해 Jira 명세를 정규화한 SSoT 문서를 구축하고 라이프사이클 훅을 연동했습니다.
   - Orca ADE 디자인 모드로 UI 요소를 정밀 타깃팅하여 외과적 코드 수정(Surgical Edit)을 수행하고, Playwright MCP로 전체 사용자 시나리오를 코드로 자동 검증했습니다.

#### 정량적 성과 및 가치

- 통상 2주가 소요되는 화면 6개, API 12개, DB 테이블 3종 규모의 풀스택 시스템을 체계적 하네스 엔지니어링을 통해 **클라우드(AWS) 환경에 단 3일 만에 무장애 단독 배포**를 완수했습니다.
- 정상 파일 뒤에 5MB 초과 파일을 주입하는 고의 실패 재현 테스트에서, MinIO 내 잔여 파일 증가량을 1개에서 0개로 통제(누수 제로)하여 분산 데이터 무결성을 입증했습니다.

### [프로젝트 3] 개발 자동화 하네스 비교 평가 및 실효성 검증 실험

- **기간 / 역할**: 2026.08 ~ 2026.09 (약 3주) / 가설 수립, 샌드박스 격리 파이프라인 구축, 실행 자동화, 데이터 분석 및 사내 보고서 단독 작성 (기여도 100%)
- **핵심 기술**: Harness Benchmarking, CRAP Metric, Mutation Testing, Git Worktree Namespace Isolation, Static Analysis, tmux

#### 배경 및 문제 정의

- **무인 코딩 에이전트 도입 타당성 검증**: Jira에 등록된 프로덕션 백엔드 결함을 자율 해결하는 코딩 에이전트(Prime Agent 등)의 도입 여부를 판단해야 했습니다.
- **거짓 완료 및 품질 사각지대**: 단독 실행 결과만으로는 타 하네스 대비 우수성을 입증할 수 없었으며, 코딩 에이전트가 문제를 해결하지 못했음에도 "작업 완료(DONE)"를 선언하는 조기 종료(False Completion), 기존 정상 코드를 훼손하는 회귀(Regression), 지나치게 난해한 스파게티 코드를 양산하는 복잡도 문제가 발견되었습니다. 이에 따라 단순 기능 해결 여부와 코드 품질 위험도를 분리 측정할 결정론적 실험 체계가 요구되었습니다.

#### 핵심 공학 구현 및 시스템 가드레일

1. **데이터 오염(Anti-Contamination) 차단을 위한 클린룸 벤치마크 파이프라인**:
   - 사내 프로덕션 백엔드 결함 3건을 선별한 뒤, `Git worktree` 기반의 파일시스템 네임스페이스 격리 파이프라인을 구축하여 에이전트가 정답 커밋(Golden Commit), 평가용 숨김 테스트, 외부 이슈 메타데이터에 사전 접근하는 Oracle Leakage를 물리적으로 원천 차단했습니다.
   - 로컬 사용자 환경 및 캐시 편향을 완전히 통제한 상태에서 계획된 261회 중 253회의 유효 벤치마크 실험(1차 11개 하네스 조합 99회, 2차 모델 고정 100회, 3차 품질 통제 조건 54회)을 완수했습니다.
2. **4대 결정론적 평가 지표(Deterministic Metrics) 설계 및 직교적(Orthogonal) 분리 측정**:
   - ① **기능 해결률 (Functionality)**: 독립적인 사후 검증 테스트셋(Held-out Test Suite) 전수 통과 및 기존 기능 회귀 실패 0건 검증
   - ② **종료 수렴도 (Completion Accuracy)**: 에이전트의 완료(DONE) 선언과 실제 기능 통과 여부를 대조하여 거짓 완료(False Completion) 색출
   - ③ **코드 위험도 (CRAP - Change Risk Anti-Patterns)**: 순환 복잡도(Cyclomatic Complexity)와 커버리지를 결합하여 에이전트가 작성한 코드의 잠재적 결함 위험 측정
   - ④ **테스트 견고성 (Mutation Score)**: 인위적 코드 변이(Mutants)를 주입하고 에이전트가 자체 작성한 테스트의 결함 탐지 및 격추율 측정 (사후 검증 테스트는 품질 채점에서 엄격히 제외)
3. **품질 게이트 강제의 실효성 및 공학적 트레이드오프(Trade-off) 규명**:
   - 3차 실험(54회) 분석 결과, 6개 조건 중 목표가 없던 **A 조건(기본 조건) 대비 최적 조건인 C 조건(수치 목표 강제)**을 비교했을 때, 최대 CRAP 지수는 평균 76.08에서 6.56으로 **91.4% 급감**했고 돌연변이 검출률(Mutation Score)은 51.7%에서 97.4%로 **45.7%p 대폭 향상**되었습니다.
   - **[핵심 아키텍처 인사이트 도출]** 통계적 상관관계 분석 결과, 엄격한 품질 게이트는 기능 해결을 촉진하는 유도제가 아니라 기준 미달의 임시방편 패치를 기각하는 필터로 작동하므로, 에이전트의 수렴 반복 횟수(Iteration Steps)와 소요 시간을 증가시키는 트레이드오프가 존재함을 실증했습니다.
   - 이를 통해 **"AI 코딩 하네스의 품질 게이트는 기능 구현 속도를 높이는 도구가 아니라, 추론 비용을 지불하여 잠재적 결함 밀도(Defect Density)를 통제하고 장기적 코드베이스의 회귀 회복력(Regression Resilience)을 획득하는 방어적 안전망(Safety Gate)"**이라는 엔터프라이즈 도입 가이드라인을 수립했습니다.

#### 정량적 성과 및 가치

- 253회에 달하는 실험 데이터를 3건의 심층 기술 보고서로 정리하여 경영진과 시니어 엔지니어들의 사내 코딩 도구 도입 의사결정에 결정적 근거로 활용되었습니다.
- 6개 품질 조건 중 비용 대비 효율이 가장 우수한 조건(작업 시간 약 22.7% 단축)을 선별하여, 이후 오픈소스 품질 게이트 개발의 표준 파라미터로 정립했습니다.

#### 핵심 공학 구현 및 시스템 가드레일

1. **ReAct 소거 실험(Ablation Study) 기반 태스크 복잡도 적응형 분기 아키텍처 구현**:
   - 8개 에이전트 파이프라인 전반에 ReAct와 Reflection 루프를 일괄 적용할 경우, 단순 데이터 추출 노드에서 모델이 자체 생성한 내부 독백(Internal Monologue)에 주의가 편향되어 원본에 없는 수치를 왜곡하는 과잉 에이전틱 환각을 유발함을 규명했습니다.
   - DeepEval 기반 9종 메트릭을 활용해 3단계 소거 실험([1단계: Direct Extraction], [2단계: ReAct], [3단계: ReAct + Reflection])을 수행했습니다. 그 결과 단순 추출 노드에서는 추론 루프를 전면 제거한 1단계 구성이 오히려 추출 정확도를 10.67%p 개선하고 사실 충실도(Faithfulness) 94.49%를 기록함을 입증했습니다.

2. **계층형 상태 격리(Hierarchical State Scoping)를 통한 컨텍스트 포화 병목 해소 (-71% 토큰 절감)**:
   - 4단계 섹션 분할 보고서 생성 시, LangGraph 전역 상태(Global State)에 7만 토큰 규모의 원천 데이터가 지속 누적되어 최종 섹션에서 컨텍스트 한도(28만 토큰)를 초과하며 프로세스가 강제 중단되는 컨텍스트 포화 병목을 확인했습니다.
   - 전역 상태 누적 방식을 폐기하고, 각 노드가 필요한 도메인 데이터만 참조하도록 세그먼트별 독립 페이로드 격리 구조로 전환했습니다. 이전 섹션의 컨텍스트는 전체 원문을 인계하는 대신 '핵심 결론 인터페이스 요약문'으로 압축 주입하여 서사의 맥락적 연속성을 유지했습니다.
   - 섹션 간 정보 중복을 원천 차단하여 파이프라인 총 입력 토큰량을 28만 토큰에서 8만 토큰으로 71% 절감하고, Lost-in-the-Middle 현상 없는 무장애 완주 파이프라인을 구축했습니다.
3. **Hybrid RAG 및 블랙박스 해소 출처 동시 제공**:
   - pgvector 기반의 코사인 유사도 의미 검색과 한국어 형태소 분석 기반 BM25 키워드 검색을 상호 결합한 Hybrid RAG를 구축하여, 정확한 법률 수치 조항과 자연어 질의의 맥락적 유사 문서를 오차 없이 동시에 검색하도록 구현했습니다.

- **핵심 기술**: LangGraph, SPO 기억 구조, PGroonga 전문 검색, pgvector, Redis, DeepEval

#### 배경 및 문제 정의

- **자유 대화형 게임 NPC의 기억 왜곡 및 레이턴시 한계**: 기존 게임 NPC의 고정 선택지 한계를 돌파하기 위해 자유 발화를 기억하는 AI 에이전트를 설계했습니다.
- **Mem0의 구조적 한계와 상태 충돌**: 오픈소스 Mem0 라이브러리 도입 시 발화자 귀속 정보가 유실되어 유저의 선호를 NPC 자신의 기억으로 착각하는 **화자 왜곡(Speaker Distortion)** 결함이 발생했습니다. 또한 대화가 누적될수록 응답 지연이 8.5초까지 치솟고, 상위 개념 질문("좋아하는 과일?")에 하위 기억("사과")을 연상 회상하지 못하는 한계가 존재했습니다.

#### 핵심 공학 구현 및 시스템 가드레일

1. **화자-주체 분리 기반 주어·서술어·목적어(SPO) 장기기억 독자 구축**:
   - 오픈소스 Mem0 도입 시 사용자가 "나 민트초코 싫어해"라고 말했을 때 주체가 빠진 채 저장되어, NPC가 이를 자기 자신의 취향으로 오인하는 화자 왜곡 문제를 규명했습니다.
   - 이에 Mem0를 걷어내고, 대화에서 주어(Subject)·서술어(Predicate)·목적어(Object)를 추출하여 '말한 사람(화자)'과 '사실의 주체'를 독립적으로 구분해 저장하는 PostgreSQL 기반 기억 시스템을 직접 구축했습니다.
   - 취향이 바뀌었을 때(예: "사과 좋아해" → "사과 싫어졌어") 이전 기억을 완전히 삭제하면 대화의 흐름이 끊기므로, 이전 기억에 유효 종료 시각을 기록하여 현재 검색 대상에서는 제외하되 과거 변화 이력으로 온전히 보존했습니다.
2. **상위 범주 키워드 확장을 통한 연상 회상 지원**:
   - "사과를 좋아한다"고 저장되어 있어도 "내가 좋아하는 과일이 뭐지?"라는 상위 개념 질문에는 대답하지 못하는 한계를 해결하기 위해, 기억을 저장할 때 '과일', '음식' 같은 상위 범주 키워드를 백그라운드에서 함께 추출해 인덱싱했습니다.
   - 의미 유사도 검색(pgvector)과 형태소 키워드 검색(PGroonga 전문 검색), 최신성, 중요도를 결합한 랭킹 방식을 적용하여 추가 LLM 호출 없이 한 번의 검색으로 자연스러운 연상 회상을 구현했습니다.
3. **기억 갱신 및 조건부 요약을 통한 대화 맥락 유지**:
   - 대화가 길어지면서 발생하는 토큰 한도 초과와 문맥 왜곡을 방지하기 위해, 중복된 기억을 정리하고 오래되거나 중요도가 낮은 대화는 조건부 요약 및 중요도 정리를 거쳐 압축 관리함으로써 긴 대화 세션에서도 핵심 맥락이 유지되도록 했습니다.
4. **호감도·정신 상태·기억 해금에 따른 대사 동적 조정 (상태 정합성)**:
   - 단순 챗봇을 넘어 게임 캐릭터로서의 생동감을 극대화하기 위해, 플레이어와의 대화 내용에 따라 변하는 '호감도 수치', 스토리 진행에 따른 '정신 상태', 던전 탐험을 통해 되찾은 '기억의 해금 단계'를 종합하여 NPC의 대사 어조와 감정 표현이 유기적으로 달라지도록 상태 머신과 동적 프롬프트를 연결했습니다.
5. **실시간 유저 인터럽트 처리 및 응답 속도 단축 (8.5초 → 2~3초)**:
   - NPC끼리 대화를 나누는 도중 플레이어가 중간에 끼어들었을 때, 이후에 이어질 대화가 DB나 캐시에 잘못 저장되는 데이터 꼬임 현상을 막기 위해 체크포인트와 캐시를 즉시 되돌리고 대기 중인 기억 저장 작업을 일괄 취소하는 인터럽트 파이프라인을 구축했습니다.
   - 대화 응답에 필수적인 기억만 먼저 읽고 신규 기억 저장은 백그라운드로 완전히 분리하여, API 응답 시간을 8.5초에서 2~3초대로 대폭 단축했습니다.
6. **이종 직군(언리얼 개발팀) 간 아키텍처 조율**:
   - 초기 언리얼 팀이 제안한 호감도-기억해금도 단일 파라미터 규격에 대해, 호감도 하락 시 기해금된 기억이 다시 잠기는 논리적 모순을 지적하고 논리적 근거로 설득하여 두 파라미터를 엄격히 분리함으로써 대화에 따른 유기적 감정 변화와 영구 기억 유지를 양립시켰습니다.

#### 정량적 성과 및 대외 검증

- 메모리 검색 지연 3.5초→1.0초 단축, 전체 API 응답 시간 8.5초→2~3초 단축을 달성했습니다.
- 4개 캐릭터 및 6개 대화 유형에 대한 DeepEval 페르소나 일치도 평가를 71.60%에서 86.67%로 향상시켰습니다.
- WANTED POTENUP 언리얼×AI 융합 프로젝트에서 최종 **최우수상(전체 1위)**을 수상했으며, **"AI를 제거하면 핵심 재미가 사라지는 독보적인 융합 작품"**이라는 심사위원단의 극찬을 받았습니다.
- 원티드랩 교육과정 김아름 운영총괄로부터 **전체 기수 중 유일한 공식 추천서**를 수령했으며, **동료 투표 4회 중 2회 최다 득표**를 기록했습니다.

#### 정량적 성과 및 가치

### [프로젝트 9] 보이스피싱 실시간 탐지 파이프라인 (PLM/LLM QLoRA 파인튜닝 & 안면인식)

- **기간 / 역할**: 2025.09 · 약 2주 / 3명 팀·팀장, PLM/LLM 파인튜닝 및 안면인식 파이프라인 설계, 발표 (기여도 50%)
- **핵심 기술**: KoELECTRA, Gemma-2B, QLoRA, PEFT, YOLOv8, ArcFace, FastAPI, Python

#### 배경 및 문제 정의

- 기존 사후 신고 내역 조회나 발신번호 블랙리스트 기반 탐지 방식으로는, 통화 도중 실시간으로 발생하는 신종 보이스피싱 수법이나 고도의 심리적 사기 위험을 포착하기 어려웠습니다.

#### 핵심 공학 구현 및 시스템 가드레일

1. **비동기 하이브리드 추론 파이프라인 (PLM + LLM)**:
   - 통화 음성 텍스트에 대해 경량 사전학습 모델인 KoELECTRA를 활용해 1차 실시간 고속 분류(저지연 위험 감지)를 수행했습니다.
   - 사기 의심 구간에 대해서는 소형 오픈소스 언어모델인 Gemma-2B를 QLoRA(양자화 기반 매개변수 효율적 파인튜닝) 기법으로 전이 학습시켜 심층 맥락과 인과관계를 비동기로 정밀 분석하도록 이원화 파이프라인을 구축했습니다.
2. **소형 모델 출력 방어 (4단계 정규식 복구)**:
   - 파라미터가 작은 소형 LLM(2B) 특성상 시스템 프롬프트 제약에도 JSON 파싱 오류가 발생하는 한계를 방어하기 위해, 정규식 기반의 4단계 텍스트 슬라이싱 및 fallback 파싱 복구 로직을 구현하여 런타임 중단 없는 안전성을 확보했습니다.
3. **생체 보안 강화를 위한 안면 인식 연동**:
   - YOLOv8로 통화자의 안면 영역을 실시간 바운딩 박스로 검출하고, ArcFace 임베딩 벡터 간 코사인 유사도를 대조해 본인 여부를 이중 확인하는 생체 인증 모듈을 연동했습니다.

#### 정량적 성과 및 가치

- 검증 대화 16건 벤치마크 테스트에서 **PLM 16/16건(100%), LLM 11/16건(68.8%)의 정답률**을 달성하여, 실시간 탐지와 심층 맥락 추론의 상호 보완 파이프라인의 실효성을 입증했습니다.

### [프로젝트 10] 표정·음성·텍스트 멀티모달 우울증 판독 시스템

- **기간 / 역할**: 2025.08 · 약 2주 / 3명 팀·팀원, 이미지 AI 파이프라인 설계 및 모델 고도화, 발표 (기여도 35%)
- **핵심 기술**: Grad-CAM, ResNet, ConvNeXt, PyTorch, Face Detection, Image Preprocessing Cache

#### 배경 및 문제 정의

- 설문지나 단일 생체 신호에만 의존하던 기존 우울증 진단의 한계를 극복하기 위한 팀 프로젝트에서, 담당했던 이미지 분류 모델이 환자의 실제 '안면 표정'이 아니라 촬영 장소의 배경 가구, 조명, 옷 색상 등 배경 노이즈에 과적합(Shortcut Learning)되는 문제를 발견했습니다.

#### 핵심 공학 구현 및 시스템 가드레일

1. **Grad-CAM 기반 지름길 학습(Shortcut Learning) 진단**:
   - 합성곱 신경망의 마지막 계층 특징 맵 활성화 영역을 Grad-CAM(Gradient-weighted Class Activation Mapping) 히트맵으로 시각화하여, 모델의 판단 근거가 안면이 아닌 배경 벽지와 조명에 비정상적으로 집중되어 있음을 시각적으로 규명했습니다.
2. **350GB 대규모 데이터셋 얼굴 검출 및 사전 캐싱 파이프라인 구축**:
   - 350GB, 17만 장에 달하는 대규모 안면 영상 데이터셋에 대해 사전 얼굴 검출 및 타이트 크롭(Tight Crop)을 일괄 수행하고 오프라인 캐시 디렉터리로 정규화 적재했습니다.
   - 이를 통해 에포크(Epoch)마다 반복되던 전처리 오버헤드를 제거하여 **모델 재학습 준비 시간을 5~6시간에서 수초(파일 I/O 로딩)로 극적으로 단축**했습니다.
3. **최신 합성곱 아키텍처(ConvNeXt) 도입 및 파인튜닝**:
   - 표준 ResNet 구조를 넘어 대형 커널과 개선된 정규화 설계를 적용한 최신 ConvNeXt를 도입하고 안면 감정 분류 전이 학습을 수행했습니다 (음성 및 텍스트 멀티모달 결합은 팀원 구현).

#### 정량적 성과 및 가치

- 검증 데이터셋에 대한 F1 Score 평가 결과, **ResNet 원본 0.7009 → 얼굴 크롭 적용 0.7535 → ConvNeXt 파인튜닝 0.7562**로 단계적이고 유의미한 성능 향상을 검증했습니다.
